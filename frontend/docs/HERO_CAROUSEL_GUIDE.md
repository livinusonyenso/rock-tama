# Five-slide hero: implementation and learning guide

Owner-authorised D-102. This replaces the earlier three-product selector with a full text-and-bottle carousel; navigation and other homepage sections keep their existing components. The attached waterfall mockup guides the composition. Final artwork/visual approval remains pending.

1. **Data first.** `content/hero-slides.ts` exports a typed readonly `HeroSlide[]`: identity, title, description, CTA, route key, image path/alt and optional occasion/concept flag. `content/hero.ts` holds the stationary brand introduction. Edit copy here without touching carousel state. These event designs invite enquiries and do not create confirmed catalogue products or prices.
2. **Render on the server.** `HeroSection.tsx` resolves routes and constructs text/button, image and shared-icon nodes. One `next/image fill` waterfall is outside the moving panels; it is decorative (`alt=""`, `aria-hidden`) and preloaded with `sizes="100vw"`. First bottle is also preloaded; remaining bottles use responsive sizes and lazy loading. There is no flattened bottle/background composite or animated scenery.
3. **Isolate interaction.** `HeroCarousel.tsx` is the only carousel Client Component. `index` selects both copy and image; `previous` and `direction` identify the outgoing bottle's side. `playing`, `hovered`, `focused` and `hidden`, plus the reactive motion preference, derive `rotating`. Manual selection pauses playback until Play; focus/hover still pause after Play until the user leaves the carousel.
4. **Schedule carefully.** An effect creates a six-second interval only when rotation is allowed. Its cleanup clears the interval on pause, index change or unmount. Visibility and matchMedia subscriptions remove their listeners. An incrementing request token cancels outdated asynchronous selections and unmount work. `autoAllowed` also cancels pending automatic navigation when playback pauses.
5. **Decode before showing.** The selection function activates eager loading for the target DOM image and awaits `image.decode()` before changing `index`. This avoids showing an undecoded incoming bottle on a slow connection. Decoding failure is caught so navigation does not get stuck; the normal image alt/error and browser verification still expose asset failures. The waterfall element never changes during selection.
6. **Animate without resizing.** All copy panels occupy the same CSS grid cell, keeping the tallest panel's natural size in layout. Hidden panels are transparent, inert and aria-hidden. Bottle frames are absolute inside one reserved stage: 288×320px mobile (width constrained to available space), up to352×416px tablet, up to384×560px desktop. `object-contain` preserves the full transparent bottle. Opacity and horizontal translate transition for600ms; text fades/rises8px. No image is remounted per selection, and no layout property or background position animates.
7. **Adapt the layout.** Below768px: introduction/copy → bottle → controls. At768px: two columns with the controls spanning both. Dot targets and arrows/play are44px, wrap into separate rows on narrow screens, and remain keyboard buttons. Touch/pen swipes on the bottle use a45px threshold and require horizontal movement greater than vertical movement×1.2; `touch-action:pan-y` preserves page scrolling. Pointer cancellation clears the gesture.
8. **Keep accessibility in state.** One named carousel region; five labelled slide groups; one current copy and image exposed. Dots use `aria-pressed`, controls have action names, announcements are off during autoplay and polite during manual selection. With reduced motion, automatic playback is disabled and transitions/entrances are removed; manual arrows/dots/swipes still work. Without JS, first-slide text, bottle and live CTAs remain available. Background stays static in every mode.
9. **Connect real destinations.** Standard CTAs go to `/shop`; Request Wholesale stays `/wholesale`. Custom slides go to `/custom-labels?occasion=wedding|memorial|coronation`. The new page reuses `EnquiryForm` and the existing validated server delivery action; `CustomLabelEnquiry` safely maps the occasion to an editable message. Existing product options and runtime delivery errors stay honest. It is an enquiry page, not an unimplemented design editor or checkout.

## Assets and regeneration

`node scripts/prepare-hero-carousel-images.mjs` creates the six optimized files in `public/images/hero/`: waterfall-bg.webp, bottle-750ml.webp, bottle-1-5l.webp, wedding.webp, memorial.webp, coronation.webp. Source filenames, hashes, dimensions, alpha and bytes are in `docs/assets/hero-carousel-manifest.json`; originals are archived under `docs/assets/source/hero-carousel/`. Selected supplied PNGs were copied from their actual names (`image.png`, `image copy.png`, `image copy 5.png`); supplied files with other names were not guessed into the remaining roles.

The owner authorised generating the missing memorial and coronation concepts. Both were generated using the supplied 750ml bottle as a shape/style reference, one transparent bottle per call, then inspected for complete silhouette, alpha and label wording. Memorial: ivory/forest label, white lily, “ROCK-TAMA”, “In Loving Memory”, “Natural Spring Water”. Coronation: forest/ivory/gold ornament and generic crown, “ROCK-TAMA”, “Royal Celebration”, “Natural Spring Water”. Prompt constraints: no scenes, personal names/portraits/dates, real royal insignia/endorsements, prices, certifications or scientific claims. Generated original PNGs are archived and optimized alongside the supplied images. These are proposed mockups, not client-approved products. Supplying final client artwork can replace their image paths without changing carousel logic.

D-103 refinement: at the owner’s request, the visible toolbar row is removed. Controls remain in the accessibility/tab order and reveal only on keyboard focus as an absolute overlay; no focus-induced reflow. Pointer/touch users keep autoplay, hover pause and swiping. Regression journeys focus the retained controls before activating them.
